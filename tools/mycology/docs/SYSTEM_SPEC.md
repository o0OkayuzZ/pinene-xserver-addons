# 最終統合仕様 v1.1.0-rc1

この仕様と `data/mushrooms.json` が正本。過去の単体鑑定案、茶15種案、画像中の空き枠・重複ID、NPC台詞案を実装しない。

## 1. 範囲

赤15・茶20、計35種。新しい地形生成や天然キノコブロックは追加しない。バニラ赤/茶は従来用途を維持し、NPCで任意に鑑定できる。
鑑定済みアイテムはゲーム用の実在菌モチーフ。茶には白・灰・地味な色の種も含む。現実の食用判断ツールではない。

## 2. 鑑定

費用はv1無料。色を選ぶとインベントリの昇順で最初に見つかる該当スロット1個を対象とする。64個未満でもその全量を使う。19個＋64個なら最初は19個だけ。UI上に今回の数量と総所持数を表示する。

1個につき独立した重み付き抽選。同じ色の各種に `2^(10-rarity)` の整数ウェイトを与える。レア度を先に選ぶ抽選、種類ごとの別補正、天井、採取地追跡はない。
現構成の合計は赤2899・茶3183。★10の1回あたり確率はそれぞれ1/2899、1/3183であり、将来の追加で正規化後確率は変わる。

結果は同種を集約し、元スタックと同じ合計個数を付与。ほかのスタックは消費しない。元スロットが空くことも考慮して収納を計画し、既存の名前やメタデータを持つスタックを勝手に潰さない。

NPCが死亡・消滅・別ディメンション・8ブロック超になっていればコミットを拒否。残りを再抽選せず保留状態を保持する。同期コミット中にawaitは禁止。

## 3. 満杯・障害

入らない分だけプレイヤーの足元へ種類ごとのスタックで落とす。結果が最大35種類に及ぶことはなく、赤最大15／茶最大20種類。

プレイヤーDPに取引記録を置く。通常の書込例外はインベントリのクローンへ復元。出力失敗は結果を固定したまま再配布。プロセス強制停止などで『書いたか不明』『spawnItem後に記録保存できたか不明』の場合は自動再実行せず管理者確認待ちとする。

**Bedrock APIはデータベースのトランザクションではない。強制終了のあらゆる瞬間で、完全な無損失・exactly-onceを保証するとは書かない。** 保留レシートを残し、無言の削除や無制限の再抽選を防ぐ。
落としたアイテムには通常の溶岩・爆発・消滅・他プレイヤー回収が適用される。所有権保護はv1にない。

## 4. 図鑑

NPCから標準ActionFormDataで開く。1ページ10種。発見前はIDと？アイコンのみで、名前、レア度、毒性、科学説明を隠す。発見後はゲーム効果、科学説明、ゲームへの対応、鑑定士のブラックジョーク。

登録は自分が鑑定を完了した時。譲渡・拾得・/giveでの所持は自動登録しない。個人の進捗は30bit単位の数値DPに保存する。`indexInGroup` はIDに対応し永久固定。

`pinene:myco_seen_red_0`、`pinene:myco_seen_brown_0`… のword番号を増やす。index30はword1/bit0。JSの32bitシフトの折返しを使わない。旧 `pinene:myco_red_seen` / `brown_seen` はword0に移行し、元の値を保持。

本文は `.lang`、制御はJSに分離。日本語本文をen_USにもフォールバックとして入れ、英語設定の端末でもキー名の露出を防ぐ。英訳は未実装。
研究ポイント・実績システムは将来用。★10は食べられない標本で、専用音・派手な演出・バニラ経験値は与えない。

## 5. 食品・特殊使用

効果強度・時間・満腹度はregistryの数値を使う。全品64スタック。食料は1.6秒、満腹でも使用可、共通クールダウン4秒。同種の効果時間は加算せず、弱い効果で既存の強い効果を下げない。

R15/B15は非食料。B06は握り潰す使用アイテムで、食料コンポーネントなし。R06は防具・吸収を無視する固定2HPコスト、生存時のみ強化。
R07/R11は摂取時に一度だけ乱数。R13は0・3・6秒だけ範囲検索、最大32体の非プレイヤー生物へ短い胞子粒子。透視・輪郭発光ではない。
B06は周囲4ブロックの非プレイヤー生物へ鈍化II・5秒、本人に吐き気3秒。NPCは範囲効果から除外。

R14は2秒、B16は20秒の遅延毒。保留がある時だけ1秒間隔で処理し、残りtickをDP保存する。同種を再摂取しても発症を先送りできない。ログアウトは残り時間を停止し、復帰後に再開。通常終了／再起動で取消にはしない。死亡/リスポーンで保留を消す。

ゲーム内の牛乳で保留毒も解除する。発症後の標準効果はバニラの牛乳処理に委ねる。**現実のキノコ中毒の治療を示す仕様ではない。**
ポーション素材、加熱料理、レシピ、売買は空欄の将来用。今回作らない。

## 6. NPCの出現と寿命

自然スポーンテーブルに混ぜず、世界共通の専用抽選。対象はオーバーワールドの地表付近にいる非spectatorプレイヤー。キノコ島に適格者がいるとその集団から1人を選び、いなければ通常候補から1人選ぶ。

|項目|通常|キノコ島|
|---|---:|---:|
|抽選間隔|15アクティブ分|同じ|
|成功率|4%|20%|
|滞在|30分|45分|
|同時自然個体|有効なlease1件|世界共通|
|生成距離|24–48ブロック|同じ|

スポーン時計は1分ごとに一度だけ更新し、オーバーワールドに対象プレイヤーがいない間は進めない。15分周期の残りを保存する。NPCがいる場合も時計自体は巡回する。死亡後の次の定期判定から候補に戻し、追加の罰則はない。

成功確率から計算した名目平均待ち時間は通常6.25時間／島1.25時間。ただし全体上限、適格者不在、位置探索失敗、複数人への対象分散を含まない。『全員が必ずその時間で遭遇』ではない。

候補地点はロード済みの安全な最上面。最大16地点まで探索。足元に固体、体と頭は空気、水・溶岩・火・葉などは避ける。周辺の足場も確認。近くの他プレイヤーにも24ブロック以上の距離を置く。生成のためのtickingarea・強制ロードはしない。

キノコ島はBedrockの `mooshroom_island` タグを優先して検査し、`mushroom_island` / shore IDを補助にする。Javaの `mushroom_fields` をそのまま流用しない。

## 7. アンロードと終了

自然個体へtoken、worldへentity ID＋token＋期限を保存する。`getEntity`が取れないだけで死亡と判定しない。チャンクを離れたことだけでは退場させない。

**寿命は実時間（Date.now）で進み、サーバー停止中も経過する。** スポーン時計とは別。復帰時に期限を超えた自然個体は取引前に除去する。新しい有効leaseができた後で古い個体がロードされた場合も、古いtokenを除去する。保存チャンク内の全レコードを強制ロードして物理的に数えた『1体保証』ではなく、有効な自然個体を1体に限定する方式。

期限時に既にNPC画面のセッションがある場合だけ最大5分猶予。猶予中は新規セッションを始めない。画面を開き直して延長し続けることはできない。退場はremoveで、死亡ドロップを起こさない。名前札・ボート等で寿命は無期限にならない。

## 8. 死亡

HP40、非戦闘、歩行・注視・被弾逃走・水や危険ブロックの回避。高度な採集AI、ムーシュルーム誘導、夜の特殊挙動はなし。

有効な自然tokenを持つ鑑定士の死亡時だけ、赤色キノコ64・茶色キノコ64を各1スタック生成。Lootingや所持小物による増加はない。管理者summon・スポーンエッグはtokenがないので0。期限退場も0。

固定Script出力であり、`doMobLoot`による制御はv1では行わない。落下・炎などプレイヤー以外の死亡原因も対象。ドロップ自体が溶岩等で失われる通常挙動は防がない。

## 9. 性能予算

常時インベントリ走査0、毎tick全Mob走査0。NPC出現時計は1分に1回。図鑑／鑑定は操作時だけ。遅延毒は保留対象者だけ1秒に1回。期限には一度のタイマーと、UI猶予中のみ最大30回の確認。R13は3回限定。
描画モデルと低解像度PNGにまとめ、大型コンセプト画像・解説資料・テストはRPへ入れない。具体的なTPS/メモリ増分は実測前に断定しない。
