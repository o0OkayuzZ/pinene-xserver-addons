## Client compatibility build

The author release remains **2.1.3**. The integrated BP/RP version is **2.1.4** to invalidate stale client resources; this is a local compatibility build, not a claimed upstream release. BP01 is 1.0.24 and the legacy crossbow RP07 is 1.2.19. Dependencies and both registration copies match these versions.

Client testing on Bedrock 26.52 exposed additional full-stack issues:

- Dungeons reused the legacy `controller.render.custom_crossbow` name with incompatible geometry/texture aliases. Its 24 consumers now use a dedicated controller name.
- The shared player controller referenced a spear variable absent from older player definitions. It now uses the equivalent equipped-item query directly.
- Twelve painting IDs in BP01 no longer resolved. They now reference the actual `*_painting_block` definitions; corresponding BP08 duplicates are excluded. The valid catalog union is 1,023 distinct IDs, including 234 BP08 entries.
- The existing Pinenite cursed-presence override still needs the removed ancient overlay controller. Its previous definition is retained alongside the namespaced crossbow controller.
- Both legacy standby crossbow geometry definitions used a missing `bow_standby` mesh texture. They now use the existing `default` alias shared by their consumers. No charge duration, damage, FOV or reward behavior changes.

The old cached Dungeons and RP07 packs were backed up and retired, and Minecraft restarted. In the disposable world, `dungeons:veiled_crossbow` was obtained and its held model rendered; `dungeons:trial_totem_stone` was placed on its required trial-spawner support and rendered. This is a limited client smoke test, not exhaustive combat or dungeon progression coverage.

Six Dungeons regression tests pass, covering catalog uniqueness/resolution, controller aliases, the player query and legacy mesh texture aliases. Metadata tests (5) and boss reward tests (4) also pass. The ownership audit passes. Local development and validation worlds received the same targeted fixes with backups; other pack versions and world data were preserved.

The local full-stack client still reports unrelated errors in Cooking Tools 0.1.3 (`placeable_food.js:10`, missing subscription event) two lighting schema errors, and remaining equipment/outline asset issues. These are not represented as resolved by this Dungeons update.


Final client log `ContentLog2026-10-04_07-20-03_1.txt` no longer reports the undefined spear variable, the incompatible Dungeons crossbow controller aliases, painting catalog errors, or the missing ancient overlay controller. **Legacy Bomb Crossbow acceptance is still failing:** its inventory icon appears, but the held model is invisible and the engine emits empty-path texture errors, even after the missing mesh alias was corrected and the old RP07 cache retired. The old model/alias mismatch is present in the pre-update source; the remaining runtime cause is not established. This release must not be described as a complete legacy-crossbow rendering fix.

Other remaining client findings are missing Parcanite tool geometry and Pinenite armor icon assets, plus the cooking and lighting errors listed above. No claim is made that the whole merged client stack is error-free.
