The 2.1.3 update was prepared as `74de23ed` and published on server main as `3e23e60e`, retaining the Infinite Castle return/chest synchronization fix from `78c5e1b0`. This follow-up applies the validated compatibility fixes on top of that published update. Source: the author's `Dungeons2.1.3.mcaddon` supplied locally.

Both Dungeons pack UUIDs are unchanged. BP uses the author's manifest format 3 and string version `2.1.3`; RP and world registrations use `[2, 1, 3]`. The BP's RP dependency is corrected from `2.1.0` to `2.1.3`. Existing dependent resource packs, both world registration copies, README and website pack registry match the release.

The original integration retained Japanese localization, project equipment and customized boss rewards. This follow-up restores nine legacy smithing/UI textures that the update removed but the Deathnerite metadata pack still references. Metadata auditing now compares format 3 string versions with equivalent format 2/world array versions, with a regression test that also rejects stale dependencies.

## Live deployment and catalog repair

Deployed to Xserver on 2026-10-04, after explicit authorization for stopping, backing up, updating and restarting production. The online player count was zero before each stop. Before installation, the server's Dungeons files matched pre-update main, with no server-only additions, changes or deletions.

Because server free disk space was only about 821 MiB, the complete offline world was streamed to the PC instead of creating another large server-side archive. The gzip integrity check passed; compressed size is 1,162,095,180 bytes. Changed addon files are separately retained under `/opt/minecraft/server/_pinene_deploy_backups/dungeons-213-20261004-validated/before`. Existing historical backups were not deleted.

The installer changed 7,169 files, verified 11,260 desired files, and confirmed that all 624 world-save files examined were unchanged during addon application. Root/world registrations and the two dependent RP manifests were updated without changing other pack versions or registration order.

Initial real-engine startup exposed an integration issue missed by JSON/syntax checks: the author's new Dungeons crafting catalog registered 389 items already owned by the existing BP01 integrated catalog. The logged duplicate-item errors were removed by excluding those existing entries from the new BP08 catalog. All 246 new/non-overlapping BP08 entries remain, and the union of 1,035 distinct catalog items is unchanged. No item definitions, recipes or reward tables were removed. A regression test checks catalog uniqueness and representative old/new items.

The one-file catalog repair was applied to production, the local development world and the disposable validation world, with the previous catalog saved before every write. Production was restarted again with zero players. Final startup at **2026-10-04 06:37:33 JST** reported `Server started.`, service `active`, Dungeons BP `2.1.3` in the active stack, and **zero errors/exceptions/failures in the latest startup/content logs**. This proves server loading/startup, not every gameplay feature or client rendering path.

The disposable client world `Dungeons 2.1.3 VALIDATION` is prepared but has not been opened. Client gameplay acceptance remains pending; switching Minecraft to the foreground was unavailable from this session.
