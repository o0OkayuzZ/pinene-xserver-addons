# Alylica's Dungeons 2.1.4 integration

The production world uses upstream 2.1.3 with local compatibility version 2.1.5. This update merges upstream **2.1.4** into the production configuration and uses local pack version **2.1.6**, preserving both pack UUIDs. The local version deliberately exceeds the installed 2.1.5 to refresh client caches; it is not an upstream release number.

Author source: https://www.curseforge.com/minecraft-bedrock/addons/alylicas-dungeons-addon-2-2/files/9393667

Source archive: `Dungeons2.1.4.mcaddon`, 24,626,044 bytes, SHA-256 `b9719e359ea3189420779fb51db429b449ad3649828faa823790d2e564d4858c`.

## Merge decisions

- Three-way comparison uses upstream 2.1.3, a fresh read of Xserver production, and upstream 2.1.4. Formatting-only JSON/text differences are ignored for classification.
- Preserve existing boss reward quantity increases, local equipment assets, crossbow/controller compatibility, crafting-catalog ownership, Infinite Castle mob events and the consolidated/throttled polling code.
- The user selected existing Japanese translation priority. Keep all 980 conflicting local translations, merge new upstream keys, and retain the local glyph atlas and localized book controls.
- Integrate Close-Spawning with the author's default ON, the `/dungeons:exithunt` command, Diamond soul display, updated bow/projectile behavior, sound definitions, ancient-hunt spawning and exit fixes.
- Preserve the local skeleton-arrow base damage of 8. Its component is migrated to the upstream entity format 1.26.50 using `anchor: eye_height`, modern bounce/damage fields, zero velocity damage multiplier and no difficulty randomization. Other projectile parameters and the castle event remain.
- Seasonal event code follows the author release. No dates are extended or rewards force-enabled.
- Update dependent RP manifests and root/world registration versions without changing UUIDs or load order. Synchronize the repository's stale nested Pinenite outline registration (1.0.7) to its existing root/manifest version (1.0.9); production already uses 1.0.9.

The deployment delta is 151 paths: 146 writes and five upstream deletions. It is built against exact production hashes and preserves every unaffected file. The upstream deleted files are one redundant enchanted-vindicator entity definition and four obsolete resource assets.

## Validation

- 25 existing boss-reward, catalog, client compatibility, performance, i18n/glyph and metadata tests pass.
- All 423 Dungeons JavaScript modules parse.
- Existing pack ownership/metadata audit passes.
- All 320 non-overlapping local-custom files remain semantically identical to production.
- Windows disposable-server startup could not load native Script API modules in any addon, including unchanged packs. This environment result is not accepted as a successful runtime validation.
- A separate disposable Linux server using production Bedrock 1.26.61.1, the production configurations/experiment flags, and the complete production addon stack started and stopped cleanly with **zero errors**. `help dungeons:exithunt` resolved the new command and its `exithunt` alias. The test used a separate empty database and closed player allowlist, without connecting to the production world database.
- Diff whitespace validation passes with value-ending spaces in `.lang` values preserved deliberately.

Existing production logs include invalid `dungeons:heavy_Crossbow` references in the ancient book, a stale-player access in sticky sludge, and an unloaded-block access in ancient-hunt code. These predate this update and are not claimed as fixed by the integration.

Deployment and Linux runtime results are appended after verification. No gameplay/client-rendering acceptance is inferred from a server startup test.
