# 昼固定で再構成・琴が止まる問題 — 2026-09-12

無限城BP 0.2.3で修正。最新ワールド（IC Phase 1）、開発用ワールド、Xserverのパックへ反映し、ファイルのSHA-256とBP登録バージョンを確認した。開いているローカルワールドでは保存・再入場後に新しいスクリプトが読み込まれる。

## 原因

背景建築の150秒周期と城本体の15分周期が `world.getAbsoluteTime()` を参照していた。最新ワールドは `dodaylightcycle=0` で、配備前の保存と問題調査時の保存はどちらも `Time=6000`。一方 `currentTick` は91,328から103,272へ進んでいた。背景の保存済み実行時刻6,200、本体24,000へ到達できず、実際のブロック変更時に鳴らす琴にも進まなかった。

城本体・背景の建築保存状態はともにcomplete、Phase 1はACTIVE。処理の削除や音量設定が原因ではなく、停止可能な昼夜時計を経過時間の計測に使っていたことが原因。

## 修正

`system.currentTick` の差分を積算する時計を共通化し、背景・本体・旧グリッド版・手動予約・残り時間表示に使用する。[公式System API](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/system#currenttick)のサーバーtickを使用し、昼夜停止・時刻変更の影響を受けない。

積算値を通常1秒ごとに保存し、スクリプト再読込時には保存値から再開する。ワールドを閉じている実時間は加算しない。最後のチェックポイントから通常最大1秒ぶんは再開後に待ち直す場合がある。

旧昼夜時計の予約とはキーを分け、修正版を初めて読み込んだ時だけ予約を作り直す。背景の初回チェックは城内にプレイヤーがいる状態で約10秒後、その後は変更完了から150秒。本体は15分。候補計画・読み込み・プレイヤー保護によって実際の開始は遅れる場合がある。

部屋・戦闘・報酬・建築の保存キーは変更しない。プレイヤー近傍の保護、本体再構成への優先権、保護で延期した場合の20秒再試行、変更開始時だけ鳴らす琴は維持する。配備時にローカルのDB・level.dat・昼夜設定へ書き込みは行っていない。

## 検証と配備

- 内部テスト45件成功（既存39件＋時計回帰6件）。
- 実際のmanagerのタイマー関数を使い、昼を6,000に固定したまま背景が200・3,200・6,200・9,200・12,200・15,200tickに、本体が18,000tickに開始し、対応する琴の呼出しがあることを確認。重いブロック配置はスタブのため、実機の描画・音声確認ではない。
- サーバーtickのリセットを伴う再読込、昼時刻の前後変更、同一tickの多重参照、保護延期、無人時の非実行を確認。
- ローカル2ワールドは変更したパック5ファイルとBP登録を反映。変更前ファイルをバックアップ。
- Xserverは接続者0人をコマンドで確認して停止し、現在の本番ワールドを全体バックアップ。パック5ファイルとroot/worldのBP登録2ファイルを反映、起動前にセーブ関連ファイル不変を確認してサービスを起動。0.2.3の読み込み・Server started・active、新規起動ログのエラー0件を確認。
