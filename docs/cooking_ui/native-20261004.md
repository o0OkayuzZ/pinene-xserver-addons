# Native cooking UI and session knife wear

The user confirmed that the intended UI is Minecraft's actual crafting screen,
with the `料理  Rank II` (or current knife rank) header and movable inventory slots.
The earlier dropdown and icon-grid deployments selected unrelated older prototypes.
This release makes `minecraft:crafting_table` the sole cooking UI, removes the
Cooking RP's form overrides, and imports the confirmed probabilistic-wear source.

## Behaviour

- 13 existing cutting-board IDs retain their models and knife rank states.
- Copper II, iron III, gold IV, diamond VI, netherite VII.
- 34 cooking results have 198 native recipe variants under private rank tags.
  The existing food pack, item IDs, stats, icons, furnace recipe, and 35 Meshy
  placeable models remain byte-for-byte unchanged.
- Existing placed knife markers migrate their saved damage on first interaction;
  that interaction is canceled, and the next opens the native screen. Multiple
  conflicting markers are preserved and rejected instead of deleted.
- Place/retrieve transfers the original knife ItemStack, retaining metadata.
- One screen with detected cooking counts once, including a Shift batch.
  Merely opening does not count. First half of base lifetime is safe, then
  failure probability rises. Base uses: gold 64, copper 96, iron 128,
  diamond 512, netherite 640. Failure is persisted and resolved on the next
  board interaction, including attempted retrieval.
- Separate players may use separate boards. One board is reserved while its
  operator remains in that session; other players cannot retrieve its knife.
  Close the screen and move slightly to hand it over. Disconnect, another block
  interaction, movement beyond 0.5 block, or the 10-minute TTL releases it.
- Retrieve the knife before breaking the board. Occupied boards cannot be mined;
  boards are immovable and explosion-proof to protect stored knives.

## Explicit limitations / engine checks still required

The published stable 2.7.0 API does not provide a native craft notification or
screen-close notification. Session detection observes a result increase together
with the matching ingredient decrease, counting inventory plus cursor. This is
conservative evidence, not a guarantee of every actual craft. Placing all materials
on the grid before an interruption, dropped output, chained recipes, closing and
remaining still, and very long sessions need real engine tests. No recipe outputs
are removed or refunded by the detector. Lifetime is not a per-output limit.

The imported prototype's four oil patterns were extended with 161 unordered mixed
seed combinations. This preserves the former form's acceptance of any eight seeds
from its four allowed kinds plus one bottle, without admitting other seed types.

Automated coverage: native runtime/wear/migration/multiplayer ownership, recipe
compiler/rank filtering, baseline gameplay preservation, and Meshy placement.
Actual PC/mobile UI, crafting, native container returns, save/reload, multiplayer
handoff, and probabilistic wear timing must be recorded separately after gameplay.
